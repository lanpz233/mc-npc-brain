# MC AI — Paper 村民 AI 插件

让 Minecraft 里的村民真正"活"起来：有独立姓名、性格、记忆、好感、恐惧、背包和交易，
能和玩家聊天、自己闲聊、对环境和事件做出反应。

- 仓库：<https://github.com/lanpz233/mc-npc-brain>
- 服务端：Paper 1.21.1 / Java 21（也可在 Leaves 1.21.1 上运行）
- 客户端：无需安装任何 mod

## 本次更新（v0.6.2）

### 打劫触发热修

- 劫财类话术（“把钱交出来”这类）补进威胁识别，之前只有打杀类狠话算威胁；

- 承诺守卫补上已完成式假交付（“已经给你了”这类）的识别，事故原话进了回归测试。

### v0.6.1 真打劫 + 每村一个主姓

- **真打劫**：给不给由村民按性格决定（模型只演、插件掷骰定“撑不撑得住”：破防概率看恐惧对胆量，胆量出生抽定）；决定给就按口头承诺真交东西。绿宝石不封顶，靠讨价还价当刹车（先哭穷开低价、被逼急才松口，物品可抵钱）。抢成一次：村庄信任 −20、好感 −30、记仇，且同一村民当天榨不出第二回。
- **每村一个主姓**：之前全服村民同姓是因为主姓是全服抽一个。现主姓按村落盘，第一个村保留原主姓，新村各自抽姓避重，个别村民带杂姓；老村民不改名。

### v0.6.0 四件套

- **背包每日刷新**：每天以昨天的背包为基底小幅增减，职业货控量不再爆仓；口粮按一天三顿保底钉死（面包 10~24），绿宝石、私人物品、玩家交易所得分毫不动。
- **商店交易等级**：跟村民买卖攒笔数升级（累计 6/16/32/56 笔升 1~4 级），等级越高货越稀有（0 级原材料 → 2 级铁货 → 3 级钻石 → 4 级下界合金，高档掺附魔货）；出生等级随机，不都从 0 级起。货单每天按“村民+天数”换新，商店名牌和面板显示等级。
- **睡觉交还原版**：删掉插件自研的找床假睡，村民按原版大脑认领自己的床、按原版作息睡；插件的疲惫只记账（睡着回落、醒着涨），没床的人就困着，不假躺兜底。
- **寻路代驾模式**：日常走路归原版导航，只有没路/没进展/卡住时自研 A* 才接管一小段（梯子、宽水等原版死角），走完立刻交还，单任务最多接管 2 次。

### v0.5.x 跟随改“狗式”

- 跟随与驾驶统一成驯服狼同款：AI 开着、用原版导航的腿，驾驶期间每 2 tick 重下当前路点，大脑的岗位/床位记忆临时钉在脚下防被日程拽走（v0.5.1 的关大脑速度直驱已被实测推翻）。

## v0.4.5

### 打劫场景的空头承诺漏网修复

实测：玩家威胁“不给我就打死你、给我你身上的所有绿宝石”，村民吓得说“反正这绿宝石也没几个了，全给你！拿稳了，别摔了！”——本轮没有任何工具调用、绿宝石纹丝没动。承诺守卫没拦住的原因：交付判定只认带主语的“我/俺/咱…给你/送你”和一张固定短语名单，“全给你”没有主语、不在名单，“拿稳了”（声称已经交到手里）更是从没被管过。

- PROMISE_GIVE 补上无主语的全量交付与完成式说法：全给你/都给你/给你了/都是你的/全是你的/拿去吧/拿稳了/拿好了（“给你了”由前置婉拒判定兜底，“不给你”不会误伤）。
- 判定表与单句判定抽到纯正则类 planner/PromiseGuard（CentralPlanner 静态初始化碰 Paper 注册表、离线测不了，老教训），新增 PromiseGuardTest 7 例，含事故原话与真交付/婉拒/价格让步的反例。

## v0.4.4

### 换物“嘴上答应、实际没换成”修复

实测事故：村民连说两次“行，换！”，东西却没换成，控制台只有一行“疑似代码残留，已整行丢弃”。三处漏叠在一起：

- **提议一轮作废**：模型在简报轮只口头答应、没调工具，提议当轮即被清掉；下一轮玩家催促时它再想成交也无提议可接。现改为提议活到成交 / 对话结束 / 登记满 3 分钟为止，本轮调了 accept_barter 才算谈完。
- **文本调用没人捞**：某模型把成交动作写成正文里的一行 `[accept_barter=message="…"]`、原生只回一个空 say。旧捞取只在“原生调用为空”时触发，有 say 就不看正文。现放宽为“原生只有台词类调用时也捞”，捞到的真动作提升为本轮决策（执行端只认第一个调用），say 的台词并进正文不丢失。
- **无前缀方括号格式不认**：方括号解析原本只认 `[动作:…]`。现新增无前缀变体（kwargs 走引号感知解析，引号内的逗号不切断值），剥离侧同步认这个格式——只删调用那一段，不再靠残余守卫把整段台词陪葬。

简报同时加了一句“光在话里说‘行，换’不算数，必须真的调用”。新增 LlmClientTextCallTest 7 例钉死事故样本。

## v0.4.0

### 偷窃系统 + 村庄信任账（服主设计）

- **偷窃**：按 F 打开村民背包后，他睡着、或醒着但没看着你（视野锥外）时，点他的东西就能偷——东西先进 2 秒托管，结算才下发（防扔地上/塞箱子躲没收）。结算时没跑掉（7 格内有视线接触，醒着的还要在他视野里）→ 85% 被抓现行：惊醒、按性格骂你、好感按赃物价值掉、记村庄信任账；跑掉了 → 只有 10% 被没收且他没看清是谁，不扣分。翻包时他转身正看见你 → 立刻关窗收网。
- **村庄信任账**（village-trust.json）：按“玩家 × 村（锚点半径 64 格）”记信任分（陌生 50）。被抓 -12、有醒着的目击者 -18；在村里做成买卖 +1/笔、每天最多 +3 慢慢赎回。以后救急系统共用这本账。村民状态卡（背包底部）能看到村里对你的信任。
- **以物抵价进商店**：买东西时可拿他收购清单上的东西顶账，进商品页点「以物抵价」，按他收购牌价**论捆计价**（零头不算），差价绿宝石补付/找零。聊天里的以物换物（accept_swap）随之删除。
- **索要系统删除**：F 界面索要、聊天讨要整套下线。想要村民的东西只剩三条路：买、等他送（含商店免费送）、偷。
- **职业设定外置**：各职业的人设与说话风格（含口头禅，如铁匠的“叮当”）搬进 professions.json，面板新增「职业设定」页签可改，保存即生效；没写的职业用内置默认。

## v0.3.2

### 睡着的村民不参与社交

- 实测：两个村民睡在相邻床位（不到 3 格），被自动闲聊凑成“邻居”聊起了“夜里寒、快回屋”——选人时没查睡觉状态。

## v0.3.0

### 事实接地：插件把事实翻译好，模型只负责表达（跨模型稳健）

起因：同一提示词下 Qwen 报时正常、云端 MiMo 七对三错——事实靠“写进提示词赌模型看”永远与模型听不听话强相关。v0.3.0 改成一套模型无关的事实层：

- **事实直答**：玩家问几点/时段、下没下雨、雨啥时停、离天黑多久、你饿不饿——插件直接拼句回答（`ai/FactAnswers`，范围卡死在短问句）。报时分两档：问时段按太阳位置说（“下午了，太阳偏西了”），问几点报插件取整的约数（“快四点了”“八点半左右”，12 小时口语）；约三分之一概率缀一句活人追问（插件拼，不经模型）。群聊旁听者遇事实问题只接话、不抢答。
- **定性状态档位化**（`ai/StateTiers`）：饥饿/疲惫/无聊/好奇/社交/好感/恐惧/伤情先翻译成档位词（饿得慌/处得不错/吓坏了…）再给模型；场景 JSON 删除原始刻度 `time_tick` 与一批原始数值（需求/好感/距离/血量全词化），数字只留给账目（库存、价格）。
- **脚下天气**（`ai/LocalWeather`）：全插件统一判定——维度（下界/末地无天气）→ 群系（沙漠/恶地/草原永不降水、雪系降水为雪）→ 世界开关。速览、场景、群聊、直答同口径。
- **天气账本**（`ai/WeatherLedger` + 注册表）：插件按世界记下雨/打雷的起止（游戏时间），存盘，默认留 7 个游戏日、更早的压成汇总一句；摘要注入每轮上下文（按村民脚下群系渲染），村民聊过去的天气必须照账说。速览另加村历（世界第 N 天）。
- **对方现状卡**：场景里玩家状态改词化呈现（距离“几步远”、血量“脸色发白，伤得很重”、饥饿观感），堵模型编玩家装备（“雨搭子”案）。
- **推理模型适配**：无工具+正文空白（思考耗光额度的典型症状）时，自动换简洁上下文（人设+速览+最近两轮）无工具重试一次。
- **主动提醒**：黄昏窗口或雷暴/降雨刚开始时，附近村民主动提醒玩家（每人每天/每场有冷却，干旱群系不提雨）。
- 面板新增“事实与翻译”组：账本保留天数、直答追问概率、报时取整粒度、主动提醒开关。

## v0.2.1

### 热修：面板打开显示“连接失败”

- **根因**：面板的几个结构化编辑器（配方/性格标签/定价/货池）引用了三个从未定义的辅助函数（detailsRow / labeledInput / textInput）。设置页不受影响，但 loadState 渲染到这些编辑器时抛错、整页被标“连接失败”——该坑自 v0.1.5 埋下，假数据测试绕开了空循环未暴露，v0.2.0 配方换全量表后必现。本版补齐三个函数，并新增两道防线：页面资源测试断言函数定义存在；`scripts/panel-dom-smoke.js` 用真实内置数据跑完整渲染冒烟。
- 配方表自动升级的日志改走插件 logger（消除 Paper 对 System.out 的 Nag 警告）。

### 1. 统一的 NPC 工具系统

把 AI 能做的事收进一套统一、可注册、可校验、可测试的框架，不再散落在各个 switch 里。

| 工具 | 作用 |
| --- | --- |
| `npc.status.get` | 查询 NPC 姓名、职业、血量、坐标、需求、恐惧、好感、当前任务 |
| `npc.inventory.get` | 查询 NPC 背包、动态价格、在售商品（含附魔） |
| `world.observe.entities` | 查询 NPC 周围真实实体（玩家 / NPC / 怪物 / 动物） |
| `npc.task.get` | 查询持续行动任务的状态与进度 |
| `npc.task.cancel` | 取消一个持续行动任务 |
| `npc.move_to` | 让 NPC 走到指定坐标（低风险行动，带距离/高度校验） |

统一请求协议 `npc-tool/v1`：

```json
{
  "protocol_version": "npc-tool/v1",
  "request_id": "uuid",
  "caller": "dialog_model | behavior_model | http | console",
  "npc_id": "uuid",
  "tool": "npc.move_to",
  "arguments": { "x": 100, "y": 64, "z": 105 },
  "success": true,
  "status": "ACCEPTED",
  "task_id": "uuid",
  "error_code": null,
  "error_message": null,
  "data": {}
}
```

- 参数在分发前按 schema 校验，未知工具、非法参数、越权调用直接拒绝；
- 查询工具同步返回；持续行动走任务状态机 `ACCEPTED → RUNNING → COMPLETED / FAILED / CANCELLED / TIMEOUT`；
- 同一 `request_id` 的结果缓存 5 分钟，重复请求不会重复执行副作用；
- 所有 Bukkit 世界读写都在 Paper 主线程，模型调用全部异步，不阻塞服务器 tick；
- 详细设计见 [`docs/ARCHITECTURE-TOOLS.md`](docs/ARCHITECTURE-TOOLS.md) 与 [`docs/TOOL-PROTOCOL.md`](docs/TOOL-PROTOCOL.md)。

### 2. 双模型架构

| 角色 | 默认模型 | 职责 |
| --- | --- | --- |
| 对话模型 | `Qwen3.5-9B-Uncensored-Q4_K_M:latest` | 人格表达、聊天、意图理解、台词 |
| 行为模型 | `minicpm-act:latest` | 只看游戏状态，选择下一步动作（不说话） |

- 两个模型共用同一套服务端权威状态与安全执行机制，不会各自维护互相冲突的游戏事实；
- 行为模型不假设原生 tool calling 可靠：优先走 Ollama 原生 `/api/chat` 并关闭思考，
  输出经 `BehaviorDecisionParser` 容错解析（裸 JSON、内联参数、think 块、代码围栏、短名 `move_to` → `npc.move_to`）；
- 解析失败会自动带上错误原因重试一次，仍失败则回退原对话模型路径，不影响服务器运行；
- 行为模型默认只接自主行动（`llm.behavior.autonomy-enabled`），不影响玩家对话。

### 3. 索要 / 交换物品规则

**F 键打开 NPC 背包后：**

- **左键**：索要该物品 **1 个**；
- **右键**：用 **主手整组物品** 与 NPC 交换该物品 **1 个**。

点击不再"静默塞东西"或"先给货再说话"，统一变成一次真实交流：

1. 关闭 GUI，NPC 进入对话状态并转向玩家；
2. 代码层把双方物品、数量、好感态度注入提示，由 NPC 的模型判断；
3. **模型明确同意才执行交付**：
   - 索要：模型调用 `give_item`，或台词明确说「给你 / 拿去 / 送你了 / 拿着 / 收下」，代码层立即从 NPC 库存交付；
   - 交换：模型调用 `accept_swap` 后，一次性完成"扣玩家主手 → 扣 NPC 库存 → NPC 物品进玩家背包 → 玩家物品进 NPC 库存"；
4. 模型拒绝 → 双方物品都不动；交换中途主手物品变了、库存不足，则整体取消，不会只扣一边。

好感仍然影响 NPC 的态度（好感越高越愿意给），但不再由代码层绕过台词直接拍板，
从流程上消除"嘴上说给你、背包里却没有"和"嘴上拒绝、东西已经到手"。

### 4. 问题修复

- 修复 `LLMClient` 静态字段初始化顺序导致的 `ExceptionInInitializerError`：
  该异常会让插件在 `onEnable` 阶段被 Paper 禁用，表现为右键无反应、村民没名字、`/ai` 全部不可用；
- 新增静态初始化回归测试，避免以后调整字段顺序再次炸服；
- 模型输出中的新工具名（如 `npc_move_to`）已并入 fallback 解析，不再出现"调用丢失、JSON 原文进气泡"。

1. **完全停止** Paper 进程（不要用 `/reload` 热更新插件）；

## 配置

首次启动生成 `plugins/MC-AI/config.yml`，改完执行 `/ai reload`（后端/模型配置）或重启服务器。

### 对话模型

只有一个模型，只负责说话；一切行为决策与结果裁决都在插件端（v0.1.4 起）。

```yaml
llm:
  # 对话模型（OpenAI 兼容接口；可只填域名或到 /v1，插件会自动补全路径）
  url: 'http://127.0.0.1:11434/v1/chat/completions'
  api-key: ''                       # 本机 Ollama 留空即可
  model: 'Qwen3.5-9B-Uncensored-Q4_K_M:latest'
  connect-timeout-ms: 5000
  read-timeout-ms: 60000            # 本地大模型冷启动较慢，建议 ≥ 60 秒
  max-tokens: 1024
  reasoning-effort: 'none'          # Ollama 下关闭 Qwen 思考；云端不支持则留空
  keep-alive: '60m'                 # 仅 url 指向本机时发送
```

模型名填 `auto` 时插件会自动探测 Ollama 当前加载的模型（30 秒缓存）。

拉取模型：

```bash
ollama pull qwen3.5-9b-uncensored-q4_k_m
ollama list
```

| 配置 | 说明 |
| --- | --- |

## 游戏内使用

### 与村民互动

| 操作 | 效果 |
| --- | --- |
| 右键村民 | 开始 / 结束对话（NPC 站定并持续面向你） |
| 直接聊天框说话 | 继续当前对话；附近未被点名的 NPC 只做附和 |
| **F** | 查看该 NPC 的背包（可在里面选他的货 + 自己的货，发起以物换物谈判） |
| **下蹲 + F** | 偷窃界面（他睡着、或醒着但没看着你时下手） |
| **下蹲 + 右键** | 打开他自家的商店（买卖 / 砍价界面，取代原版交易） |

### 管理命令

| 命令 | 说明 |
| --- | --- |
| `/ai tool list` | 列出所有已注册工具 |
| `/ai tool <工具名> <村民名> [参数... \| JSON]` | 绕过模型直接调用工具（验收/排查） |
| `/ai spawn <名字>` | 生成一个 AI 村民 |
| `/ai list` | 列出当前管理的 NPC |
| `/ai llm` | 查看当前对话后端与模型 |
| `/ai llm set <url> <model> [api-key]` | 运行时切换后端 |
| `/ai llm model <模型名\|auto>` | 运行时切换模型 |
| `/ai reload` | 重载配置与人格标签库 |

示例：

```text
/ai tool npc.status.get 汤孟和
/ai tool npc.inventory.get 汤孟和
/ai tool world.observe.entities 汤孟和 16 10
/ai tool npc.move_to 汤孟和 100 64 105
/ai tool npc.move_to 汤孟和 ~1 ~0 ~-15
/ai tool npc.move_to 汤孟和 {"x":100,"y":64,"z":105}
/ai tool npc.task.get 汤孟和 {"task_id":"<上一步返回的 task_id>"}
/ai tool npc.task.cancel 汤孟和 {"task_id":"<task_id>"}
```

参数两种写法等价：位置参数按工具 schema 声明顺序填写（`npc.move_to` 为 `x y z speed`），
也可以继续传 JSON 对象。坐标支持原版相对写法：`~` = 村民当前坐标，`~1` = +1 格，`~-15` = -15 格。

工具名也可以写模型侧的短名（如 `npc_move_to`），分发层会归一化。

### 验收要点

- 未知工具 / 缺参数 / 参数越界 / 越权调用必须返回失败且不改变世界；
- `npc.move_to` 应返回 `ACCEPTED` 和 `task_id`，到位后 `COMPLETED`，取消后 `CANCELLED`；
- 对话状态下 NPC 不得移动，已开始的移动任务应自动取消；
- 模型离线时服务器仍能正常运行，只记录 LLM 调用失败；
- 送礼/换物/打劫交割的台词必须与实际物品转移一致。

## 常见问题

**插件显示红色 / `/ai` 提示 plugin is disabled？**
看 `logs/latest.log` 里 `Enabling MC-AI` 后的第一条异常。最常见原因是装了瘦包（缺依赖）
或旧 jar 没删干净。请使用 `build/libs/MC-AI.jar`，并确保 `plugins/` 只有一个 MC-AI jar。

**村民没有名字、右键无反应？**
同上，先确认插件是否 `enabled`。

**模型请求超时或返回空？**
确认 Ollama 正在运行、模型已下载；本地模型冷启动可能超过 30 秒，把 `llm.read-timeout-ms` 调到 60000。

**砍价后价格没变？**
GUI 打开时砍价会自动关闭并重开以刷新价格；若仍未刷新，确认 `dynamicPrices` 已写入村民状态。
