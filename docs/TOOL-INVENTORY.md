## A. 统一工具柜（新系统）——共 8 件

注册点：`McaiPlugin` 第 472-479 行；统一闸门：`tool/ToolPolicyService`；
分发：`tool/ToolDispatcher`。闸门现有检查只有五项：调用方在白名单内、NPC 存在、
需要玩家上下文的工具必须带玩家、对话中禁用的工具在对话时拒绝、高风险工具需神使。
代码注释自述「规则保持最小」。

| 工具 | 干什么 | 类别/风险 | 谁能调 |
| --- | --- | --- | --- |
| `npc.status.get` | 查 NPC 状态（姓名/职业/血量/好感/任务等） | 查询 / 低 | 对话模型、行为模型、命令、外部 |
| `npc.inventory.get` | 查 NPC 背包与在售商品 | 查询 / 低 | 同上 |
| `world.observe.entities` | 查周围真实实体 | 查询 / 低 | 同上 |
| `world.observe.blocks` | 查附近方块 | 查询 / 低 | 同上 |
| `world.environment.get` | 查时间/天气/环境 | 查询 / 低 | 同上 |
| `npc.task.get` | 查持续任务进度 | 任务 / 低 | 同上 |
| `npc.task.cancel` | 取消持续任务 | 任务 / 低 | 同上 |
| `npc.move_to` | 走到指定坐标（寻路 + 任务制，可查进度可取消） | 动作 / 低 | 命令、外部等；**对话模型拿不到** |

要点：

1. 8 件里 7 件只读/管理，唯一的动作 `npc.move_to` 风险标的是「低」，
   所以闸门里「高风险需神使」这条规则**永远不会触发**。
2. 对话模型（玩家平时聊天的那个）通过 `ai/LlmToolAdapter.dialogSchemas` 只拿到
   **查询类**工具——它真正干活全靠下面 B 部分的老后门。
3. 闸门没有速率限制、没有配额、没有价值上限、没有距离校验（各工具自理）。

## B. 老后门动作（对话模型工具集）——共 19 件

定义：`ai/BehaviorRegistry`（工具名白名单 + 给模型的说明书）；
执行：`planner/CentralPlanner.executeDecision`，其中世界交互 6 件转
`security/WorldInteractionService`，权限判定在 `security/PermissionManager`。

| 动作 | 干什么 | 插件实际把关（代码，已核实） | 只靠提示词/AI 自觉的部分 | 主要缺口 |
| --- | --- | --- | --- | --- |
| `say` | 说话 | 台词清洗；空头承诺会被整句剥离（承诺守卫）；空台词有兜底 | 台词长度、内容分寸 | 基本无（表达类，本就归 AI） |
| `wave` / `nod` / `shake_head` | 肢体动作 | 无（纯动画） | —— | 无 |
| `look_at` | 转头看玩家 | 只看向当前对话玩家 | —— | 无 |
| `idle` | 什么都不做 | 无 | —— | 无 |
| `flee` | 逃跑 | 对话中不触发；事后记一条「被追过」的事实 | 何时该逃 | 无硬伤 |
| `move_to`（老版） | 移动到坐标 | 仅「对话中不动」一条；**无距离上限、无落点安全检查**，朝模型给的坐标直接推速度 | 坐标合不合理全靠模型（说明书要求它别乱编） | 与统一柜的 `npc.move_to`（寻路+任务）**重复实现**，且对话模型只能用这个糙版 |
| `follow_player` | 跟着玩家 | 对话中不跟；1 秒后复查一次（15 格内才继续） | 跟多久、跟多远 | 不是任务制：无持续跟随状态、无超时、无落盘 |
| `find_shelter` | 找遮雨处 | 20 格内找有顶方块；对话中不跑 | —— | 无硬伤 |
| `learn` | 把玩家教的东西记进永久记忆 | **代码层采信判定**：先算「信不信这个人」（熟悉度/好感/开放度），不信就不存；内容截断 40 字；违反世界观的词（金币等）拒存；存时强制带出处「听XX说」 | 内容长度建议 ≤30 字 | 是老后门里把关最像样的一个，可作搬运模板 |
| `give_item` | 把库存东西给玩家 | 物品须可解析；数量钳制 1-64；GUI 索要时玩家选的数量优先于模型参数；**非神使不能超库存**；神使凭空补差额须审计；代码层刚交付过同款物品 8 秒内防重复 | —— | **给不给靠掷骰子**（好感换算概率 10%-95%，`EmotionState.giveChance`）：与已定的「插件按规则定结果」冲突；**无稀有度门槛**（高好感掷中就能送图腾，只要有库存）；无每日上限、无口粮保留、无价值上限 |
| `accept_swap` | 同意玩家在界面里提的交换 | 换什么、换几个由**代码在点击时钉死**，模型只表态；执行前复核玩家手持物品与 NPC 库存；四步转移前校验齐全，不半执行 | **这笔交换值不值，由模型判断** | 与已定规矩冲突：应改为插件先按价值表算值不值，AI 只表态（见设计文档第 4 节方向） |
| `break_block` | 破坏方块 | 32 格距离上限；神使全放行+审计；非神使：玩家领地（以床为圆心）内一律禁拆，且仅农夫可拆 9 种作物类方块白名单 | 其他职业「不该拆家」靠说明书 | 把关其实不错；缺速率/每日配额（白名单内可无限收割——不过那正是农夫本职） |
| `place_block` | 放方块 | 32 格距离；领地判定（非领地主的亲信不能放）；非神使必须真有库存并扣 1；神使凭空放+审计 | —— | 材质只验「是方块」，无危险方块名单（靠库存里没有来兜底） |
| `teleport` | 传送自己到坐标 | 32 格距离；**落点安全检查**（岩浆/火/仙人掌/悬空/卡墙全拒） | —— | 把关完整，搬运即可 |
| `teleport_to` | 传送到目标/把目标拉来 | 传别人=神使专属；传玩家必须等其聊天回「好」（全词匹配、30 秒有效）+审计；传其他生物神使可直接拉 | —— | 把关完整，搬运即可 |
| `equip` | 穿装备/拿手上 | 必须有库存；换下的旧装备回收进库存；扣 1 | —— | 低风险，搬运即可 |
| `offer_trade` | 开店/上架/降价/下架 | 开店有代码层门卫：玩家近期没聊到交易就拦下；上架验职业可售、绿宝石不能当商品、玩家砍价锁防覆盖；降价拒绝改货币配方 | 定价合不合理基本靠模型 | **全场最乱**：① `price=0` 免费送**不扣库存、凭空造物**（单次≤16）；② 上架价格任意（≥1 即可），与价值表无关；③ 降价无下限（无砍价锁时模型想降到 1 也行）；④ 上架不验库存（能卖根本没有的东西） |

## C. 已经「插件直管」的好例子（不是模型工具，供搬运参照）

这几条不经过模型工具，是代码层直接拍板执行的，证明「插件定结果、AI 只表达」
在这套代码里完全可行，搬运时应向它们看齐：

| 流程 | 做法 |
| --- | --- |
| 索要交付 `handOverFromStock` | 玩家讨东西，代码层判定后当场出库存交付，再把「已给过」作为事实告诉模型；模型同轮再调 `give_item` 会被静默去重 |
| 收礼 `takeFromPlayer` | 模型**没有** `take_item` 工具；玩家递东西必须先登记意向、NPC 问「真要给俺？」、玩家亲口确认才真扣货 |
| 砍价拦截 `interceptBargain` | 玩家聊天报价由代码层直接改价上锁，模型不得覆盖（注：按已定方案，此路将随交易 UI 上线退役） |
| 传送确认 `consumeTeleportConfirm` | 神使传玩家须等玩家聊天回确认词，见 B 表 `teleport_to` |

## D. 跨动作的共性问题

1. **价值尺子有，但没人用**：`PermissionManager` 里有一套物品价值表
   （`itemValue` / `isRarePlus`，如钻石类 ≥100 算稀有），全仓搜索**零调用**——
   「亲信不许动稀有物品」只写在提示词里，代码从不执行。
2. **没有统一账本**：只有神使的动作进 `audit.log`；普通动作散落在控制台日志里，
   出了事查不到完整流水。
3. **没有全局速率/配额**：除个别动作自带钳制外，没有「每分钟最多 N 次动作」
   这类总闸，模型抽风时可高频重复调用。
4. **两套移动并存**：老 `move_to`（速度直推、无校验）与统一 `npc.move_to`
   （寻路任务制）行为不一致，对话模型用的偏偏是糙的那套。
5. **掷骰子做决定**：`give_item` 的概率制与已定分工原则冲突（结果应由规则
   确定性给出，随机只应存在于「表达」层，如台词和动作小 variations）。
